**Modern** is a page on the shared design system: it calls `modern()` for the
document shell and loads `mgdb-modern.css`. **Partial** has one of the two and
not the other, which usually means a page borrowing components inside the old
shell.

**Legacy splits three ways, and only one of them is work.** Counting them
together is what made the figure look worse than it is:

- **Still to convert** &mdash; a legacy page a reader can still reach from the
  modern site. This is the real backlog, and the list below is it.
- **Record page already modern** &mdash; the bare URL still serves the old
  per-type search form, but `?id=` is already dispatched to a record page on
  the record shell. Half converted, not untouched.
- **Not linked from the modern site** &mdash; nothing modern links to it. These
  are old routes superseded by a page built elsewhere, or simply unreferenced.
  They need a retirement decision, not a rebuild.

Reachability is measured two ways, and either one counts. **In the source**, a
modern-owned file links to it: a `*_modern.php` controller, an `mgdb-*` template
or script, a record library, or any PHP page that itself classifies as modern.
**In the response**, the rendered HTML of a page that came back modern links to
it &mdash; which is the only way to see a link built at run time from data, as
`/whatsnew` does when it lists recently changed records. The site map and this
report are excluded as sources: both list every URL on the site, so a link from
either says nothing about whether a page is reachable in the ordinary way.

One limit worth knowing: record routes are not probed, so a legacy page linked
only from a modern record page is seen in the source pass or not at all. A link
written against `www.maizegdb.org` does count here &mdash; the route is the same
route whichever host serves it &mdash; even though the same link is reported
separately below as an offsite link, which on a development instance it is.

## How this is measured

`tools/redesign_status.py` copies itself to the development instance, walks the
web root, and works out which URLs exist the same way the site does:

1. `controllers/<name>.php` answers `/<name>`; `controller.php` checks these first.
2. `controllers/<name>/<page>.php` answers `/<name>/<page>`. Where a
   `<page>_search.php` also exists, the bare URL is the search page and the URL
   with an identifier is the record page, so both are listed.
3. A single-segment URL with no top-level controller falls through to
   `redirect.php`, which searches `controllers/static`, `dynamic`,
   `controllers/about`, `controllers/community`, `controllers/tools`,
   `controllers/genome`, and `controllers/documentation` in that order.
4. A real directory in the web root with an `index.php` is served by Apache
   directly, because `.htaccess` only rewrites paths that are neither a file
   nor a directory.
5. Guards of the form `if (PAGE == 'x' && ...) include('..._modern.php')` are
   read out of each controller, so a page swapped in for one route without
   touching its siblings is attributed to that route alone.
6. A page modernized in place gains a `controllers/<name>.php` interceptor so
   that `controller.php` answers the URL rather than `redirect.php`. Those
   routes are categorised on the file the interceptor displaced, so a page
   keeps its category when it is modernized.

A file reachable at more than one URL is one row carrying both, so the totals
count pages rather than paths.

Each URL is then fetched over HTTP from the server itself and the response is
classified: `mgdb-modern.css` plus `class="mgdb-modern"` on the body is modern.
The live response is the verdict where there is one. Pages that sign in or out,
send mail, write to the database, or need a record identifier are not fetched;
those rows say `source` in the *How classified* column and fall back to reading
the controller.

Rerun it with:

```bash
tools/redesign_status.py
```
